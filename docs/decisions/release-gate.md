# 决策：发布门控与弃用范围

* **构建状态**：构建级硬门控只有“人工补证完整”等契约问题；示例级失败（超时/断言/a11y）只把该示例从正式页面剔除，不拖垮整站。
* **发布关系**：`releases` 记录 channel 与 `supersedes`（上一个发布版本），形成发布链。
* **破坏变更**：`breaking_changes` 必须关联 `migration_notes`（迁移说明锁定提交）与 `retest_cases`（复验案例）。发布接口在校验到破坏变更时，缺迁移说明或缺复验结果/有复验失败都会以 409 拒绝发布。
* **弃用范围按实际版本声明**：弃用来自实际发布版本的契约（v2 的 `label` 标 `deprecated.since=2.0.0`）。v2 发布时 `removed_in` 仍为 NULL（移除版本尚未发生）；当 v3 注册“removal”破坏变更时，回填 `removed_in_version=3.0.0`。因此 v1 无弃用标记、v2 为 `[2.0.0,3.0.0)`、v3 契约里彻底没有 `label`。
